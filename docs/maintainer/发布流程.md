# 发布流程（维护者用）

仓库放**源码 + 构建输入**（`.tools/src/` 源码 + `.tools/assets/` 约 42MB 资产）；
**成品是构建输出**，不进 git，只作为 Release 附件（一个分享包）分发。

## 一、发版前置检查

在干净的工作区按顺序跑完，任一步失败就不要发：

```powershell
# 1) 构建能复现（期望末行 sha256 55ad8f466eaa62d4）
python .tools/build.py

# 2) 核心校验
node   .tools/render_unit.js          # 期望 失败项: 0（27 项）
python .tools/ui_static_check.py      # 期望 失败项: 0（38 项）
python .tools/ui_contrast.py          # 期望 失败项: 0（25 项）
python .tools/syntax_check.py         # 期望通过
python .tools/launcher_check.py       # 期望 失败项: 0（.cmd 纯 ASCII / .ps1 带 BOM）
python .tools/ui_pii_scan.py          # 期望 0 处
python .tools/ui_pii_check.py --corpus .tools/corpus_text_all.txt   # 期望 PASS ※需语料

# 3) 隐私门禁：先暂存，再扫索引（这一步是硬门槛）
git add -A
python .tools/publish_check.py        # 期望 PASS（0 命中）

# 4) 从仓库内容重建一遍，确认提交的源码自足（源码与资产都在仓库内，无需额外下载）
git archive --format=zip -o repo.zip HEAD
#    解压后直接跑 build.py，sha256 应一致
```

## 二、首次建仓与推送

```powershell
# 建公开仓库（已在本地初始化并提交，故只加 remote 再推）
gh repo create score-ocr-tool --public --source=. --remote=origin --push

# 若想用别的仓库名或私有：
# gh repo create <名字> --private --source=. --remote=origin --push
```

> 提交身份已设为本仓库局部配置 `115859117+Bonger34@users.noreply.github.com`，
> 不会把私人邮箱写进公开历史。查看：`git config user.email`

**推送凭证**：正常环境下跑一次 `gh auth setup-git`，git 就会用 gh 的 token，之后不再弹窗。

### 受限环境（agent 沙箱 / 无用户级写权限）下的症状与原因

| 症状 | 原因 |
|---|---|
| `CreateFileMapping … Win32 error 5` + `sh.exe … Terminating` | 凭据 helper 是 `!'gh.exe' auth git-credential`（以 `!` 开头 = **shell 命令**），git 要用 MSYS2 的 `sh.exe` 执行它；受限环境下 MSYS2 运行时创建共享内存段被拒，`sh` 一启动就崩 |
| `could not lock config file C:/Users/<你>/.gitconfig: Permission denied` | `gh auth setup-git` 要写用户级配置，被拒 |
| `Invalid username or token` / `No anonymous write access` | helper 崩了之后回退到 Git Credential Manager，而里面是失效的旧凭据 |
| **弹出输用户名/密码的窗口** | 最后回退到 `git-askpass.exe`。**别去填**——GitHub 早已禁用密码认证，填账号密码没有用；这个窗口只是失败后的兜底 |

绕过办法（**推荐 A，完全不碰持久配置**）：

```powershell
# A) token 只进这一次的命令：不改 remote、不写配置、不调任何 helper
$tok = (gh auth token).Trim()
git -c "credential.helper=" push "https://Bonger34:${tok}@github.com/Bonger34/score-ocr-tool.git" main

# B) 若 A 不被支持，可临时改 remote，推完立刻还原
git remote set-url origin "https://Bonger34:${tok}@github.com/Bonger34/score-ocr-tool.git"
git push origin main
git remote set-url origin "https://github.com/Bonger34/score-ocr-tool.git"   # 还原
git remote -v                                                                # 确认没有 token
```

> **不要在能看到桌面的环境里跑 `git credential fill` / `git credential approve`**：
> GCM 缺条目时会弹出 GUI 输入框，等于用另一种方式打扰使用者。

## 三、创建 Release

**只传一个附件**：给使用者的分享包（HTML + 1 个启动器）。
构建资产 `.tools/assets/` 随仓库走，**不要**放进 Release——第三方库与模型单独拿出来没有用，
使用者误下只会得到一堆打不开的碎片。

```powershell
# 1) 先重打分享包（成品 HTML + 打开工具.cmd）
python .tools/build.py
python .tools/rebuild_share_zip.py     # 输出 .trae-html-share-packages/score-ocr-tool.zip
python .tools/verify_share.py          # 期望 identical: True

# 2) 发版
gh release create v2.11 `
  --title "v2.11 · 启动器更名为 打开工具.cmd" `
  --notes-file .github/release_notes_v2.11.md `
  ".trae-html-share-packages/score-ocr-tool.zip"

# 3) 把中文显示名写进 label（GitHub 不接受非 ASCII 附件名，见下方红线）
gh api -X PATCH repos/Bonger34/score-ocr-tool/releases/assets/<asset_id> `
  --input <(echo '{"label":"搜分名单查询工具.zip"}')
```

> **附件名必须纯 ASCII**：实测 GitHub 会把任何非 ASCII 附件名重置成 `default.zip`，
> 且用 API 改名也会被重置。中文名只能放在 `label` 字段（上一步），
> 附件内部的文件名（HTML 与启动器）不受影响，仍是中文。

## 五、以后每次改版

1. 只改 `.tools/src/` 下的源码（应用模块在 `src/app/`，**别手改 44 MB 的成品 HTML**）
2. `python .tools/build.py` 重建，确认 sha256 与期望一致
3. 跑完第一节的检查，尤其 `publish_check.py` 与 `launcher_check.py`
4. `git add -A && git commit -m "feat: ..."`，更新 `CHANGELOG.md`
5. 重打分享包 → 发 Release（只传那一个 zip）

## 六、红线

- `target/`、`.samples/`、`.screenshots/`、`.tools/corpus_text_all.txt`、`.tools/pii_truth.json`
  **含真实姓名/学号，永远不要提交**（`.gitignore` 已挡，但新增数据目录时要补规则）
- 提交前务必确认 `git ls-files` 里没有数据目录：
  `git ls-files | Select-String '^(target|\.samples|\.screenshots)/'` 应为空
- `.gitignore` 不支持行尾注释——注释必须单独成行，否则整行会被当成模式而失效
- 改启动器后必跑 `launcher_check.py`：`.cmd` 混入中文、`.ps1` 丢掉 BOM 都会静默失效
- **Release 附件名必须是纯 ASCII**：非 ASCII 会被 GitHub 重置为 `default.zip`，中文名只能放 `label`
