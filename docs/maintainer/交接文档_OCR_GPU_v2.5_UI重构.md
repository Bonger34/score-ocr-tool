## 进度与倒计时引擎（v2.6，改之前先读这段）

`makeProgress()` 把每一步折算成**预计工作量（毫秒）**，进度 = 已完成工作量 / 总工作量：

| 机制 | 位置 | 要点 |
| --- | --- | --- |
| 按类型计权 | `pri` + `ctl.add/step(kind)` | OCR 页 1600ms（CPU 回退 8000ms）、文本页 25ms、文件 150ms、检索按文本量 |
| 未打开文件的外推 | `handleRun` 里的 `prog.pending(...)` | `已用时 × 剩余KB/已处理KB × 1.6`，让最后几个文件也有预留份额 |
| 实测速度 | `meter()` / `effSpeed()` | 从**第一个单元完成**起算的全程平均（70%）+ 1 秒窗口 EMA（30%）；首个页面含预热，不能算进去 |
| 在途外推（creep） | `paint()` | `(距上次完成的时间) × 速度`，上限取 `剩余×0.98`、`6 页 OCR` 的较小者 |
| 刷新与单调 | `start()` / `shown` | 250ms 定时重绘；百分比单调不回退；条宽与数字同源 |
| 阶段划分 | `begin(0,98)` / `begin(98,2)` | 解析 0–98%、检索 98–100%（检索通常 <1s）；`finish()` 兜底、`finally` 停表 |

**改这个引擎时注意**：`ctl.step(kind, n)` 的 `n` 必须与 `ctl.add(n, kind)` 一致（检索阶段按文本量分权时尤其重要，
不一致会让进度停在 99%）。改完必须跑 `node .tools/prog_sim.js`（确定性对照台）确认指标没退化。

## 检索明细格式（v2.7，改之前先读这段）

明细口径来自 `notice/` 里的三份材料（通知正文 + 归档命名示例 + 闽农大金山学〔2025〕26 号，32 页），**不要凭感觉改**：

| 规定 | 出处 | 实现位置 |
| --- | --- | --- |
| 五育 = 德育 / 智育 / 体育 / 美育 / 劳育，顺序 德→智→体→美→劳 | 第五条 | `render.js` 的 `YU` / `YU_CLS` |
| 德育奖励分超出 25 分按 25 分计算 | 第九条 | `YU_CAP={'德育':25,'智育':10}`，超限时输出 `.mp-cap` 提示 |
| 同一学年智育奖励分累计不超过 10 分 | 第十三条（五） | 同上 |
| 材料按 `学号姓名/五育测评/+分值 (事由)` 归档 | `格式.jpg` | 明细层级：`.mperson`（人）→ `.mp-yu`（育）→ `.mp-item`（+分值 / 事由 / 来源文件） |

- 分值写法：加分项 `+10` / `+0.5`（不补零），小计与合计保留一位小数；负数照写。
- 材料包里的文件名按用户要求是「分值 + 原文件名」（原文件名一字不改），与明细里的 `+分值 事由` 展示口径不同。
- 事由取 `activityKey()` 清洗后的活动名；来源列是原始文件名（`title` 属性给完整名）。
- 没有学号的记录归入"未标学号"块；没识别到育别或分值的进"未标注"段，**不计入合计**。
- 台账列数随"有记录的育"变化，缺的育用一句话点名——不要为了凑五列把空的育也画出来。
- 导出 Excel 两张表：`加分证明清单`（一行一个加分项）+ `五育汇总`（一行一人 + 合计行）。
- 改完 `render.js` / `export.js` 必须跑 `node .tools/render_unit.js`（合成样本覆盖真机跑不出的德育>25 分支）。

## 材料包导出（v2.8，改之前先读这段）

「导出材料包」按 `学号姓名/五育测评/分值 + 原文件名` 打包**命中的名单原件**（文件名保持原样，只在最前面加分值），附 `说明.txt` 与 `清单.csv`。

| 机制 | 位置 | 要点 |
| --- | --- | --- |
| 来源引用 | `extractEntries` 的 4 处 `return` + `matched.push` | 只挂 `{file, zip内路径}` 与体积，**不复制字节**——持有 JSZip 的 ZipObject 会让 285MB 的包整场驻留 |
| 取字节 | `zip.js` 的 `bytesOf()` | 直接文件走 `file.arrayBuffer()`；zip 内条目按来源文件缓存已解开的 zip（同一份只解一次），导出结束清缓存 |
| 命名 | `safeName` / `personDir` / `itemFile` | **原文件名不变，只加分值前缀**（`+2 晚归打卡公示汇总.pdf`）；非法字符换 `_`、去结尾点与空格、重名加 `(2)`、截断只截名字不截扩展名；扩展名大小写保留 |
| 体积守卫 | `ZIP_CAP = 300MB` | 模糊检索会命中 458 份名单（逐项复制约 28 GB），超限直接拒绝并提示先精确检索 |

**局限**：包内是名单原件而非学生的证明材料；班级目录层要自行在外层加；同一份名单会按加分项复制到多个五育目录。
验收脚本 `.tools/ui_zipcheck.py`（`--files all --expect-cap` 另测守卫），断言包含**与来源逐字节比对**。

## 已知取舍（别当成 bug 改回去）

- 状态行里的 `3/26` 是**单元数**（页/文件），百分比是**工作量加权**——两者本就不是同一刻度，是设计口径。
- 倒计时在第一个页面完成前显示"预计剩余 计算中…"：首个页面含模型预热，用它估速度会差好几倍，宁可不显示。
- 进度条在"刚打开一个比预估重得多的文件"时会短暂停住：单调不回退 + 分母变大，只能等真实工作补上（实测 8.25s，旧版 19s）。
- 台账数字正下方的中文标签就是图例，不需要额外加图例。
- 已选文件后拖放区收成"继续添加文件"一条，且**再次选择/拖入是追加**（按 文件名+大小+修改时间 去重），不是替换；要清空请点「清空」。
- "导出 Excel 汇总"保留描边按钮样式，它是结果区唯一的次要动作。
